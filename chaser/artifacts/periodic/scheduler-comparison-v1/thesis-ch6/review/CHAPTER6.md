# 제6장 평가

본 장에서는 CHASER의 친화도 기반 태스크 배치와 실행 전 점검을 평가한다. 배치 평가에서는 캐시 친화도를 고려한 묶음 배치가 이용률과 release 구조만 고려한 배치에 비해 실행시간을 줄이는지 확인한다. 실행 전 점검에서는 동결한 RF 모델이 마감 준수 여부를 구분하고, 정적 규칙보다 실행 후 마감을 준수하는 사례를 더 많이 확보하는지 살펴본다. 학습에 사용하지 않은 커널 워크로드에는 동일한 모델과 판정 기준을 적용하여 활용 범위와 한계를 확인한다.

## 6.1 평가 설계

### 6.1.1 실행 환경과 평가 자료

실험은 GR740을 모사하는 laysim에서 RTEMS 6의 EDF 스케줄러를 사용하여 수행하였다. 네 코어의 스케줄링 영역을 구성하는 방식에 따라 Partitioned, Global 및 Clustered를 비교하였다. Global은 네 코어를 하나의 영역으로 구성하였으며, Clustered는 코어를 1+3 또는 1+1+2로 나누었다. 대상 프로그램에는 O2 최적화를 적용하였다.

각 실행에서는 240 ms의 준비 구간 이후 720 ms를 측정하였다. TET와 TAT 등의 시간 지표는 측정 구간을 대상으로 계산하였으며, 전체 마감 준수 여부는 준비 구간을 포함하여 판정하였다. 따라서 준비 구간에서 마감 위반이 발생한 실행도 마감 준수 실패에 포함된다.

부하는 단독 실행을 기준으로 정한 계획 이용률을 사용하였다. 합성 태스크의 계획 실행시간은 단독 실행 자료로 보정한 실행시간 모델에서 구하였다. 정수 반복 횟수와 보정 연산을 정한 후 해당 구현의 예측 실행시간을 주기로 나누어 계획 이용률을 계산하였다. 각 조건·부하의 첫 번째 기본 집합에 속한 태스크를 하나씩 실행하여, 준비 구간을 제외한 평균 작업 CPU 시간으로 계산한 이용률과 계획 이용률의 상대 오차가 3% 이내인지 확인하였다. 이는 모든 기본 집합의 모든 태스크를 직접 측정한 절차는 아니다. 커널 워크로드에서는 선택한 커널·배열 크기·반복 횟수의 단독 실행시간을 직접 측정하여 계획 이용률을 구성하였다.

본 장에서 코어당 부하는 태스크 집합의 총 계획 이용률을 네 코어로 나눈 값이다. 이 값은 단독 실행 기준의 실험 조건이며, 여러 태스크를 함께 실행할 때 관측되는 CPU 시간의 증가를 직접 반영하지 않는다.

평가 자료의 구성은 표 6.1과 같다. 같은 기본 태스크 집합에 서로 다른 부하나 주기 분포를 적용한 결과는 각각 하나의 평가 사례로 구분하였다. 기본 태스크 집합을 반복해서 사용한 사례들을 서로 독립적인 태스크 집합으로 간주하지 않았다.

**표 6.1. CHASER 평가 자료의 구성과 사용 목적**

| 평가 자료 | 기본 태스크 집합 | 평가 사례 | 평가 목적 |
|---|---:|---:|---|
| 합성 배치 평가 | 유형별 18개, 총 36개 | 396개 | 친화도 묶음 배치의 실행시간 및 마감 준수 특성 |
| CAAS 구성요소 비교 | 합성 배치 평가와 동일 | 동일한 396개 | 친화도 지표, 묶음 방식 및 release 고려의 기여 |
| 합성 워크로드 RF 평가 | 유형별 24개, 총 72개 | 360개 중 357개 분석 | 마감 준수 예측과 실행 여부·구성 결정 |
| 미학습 커널 7종 평가 | 24개 | 120개 중 118개 분석 | 새로운 커널에서 동결 모델의 적용 결과 |
| 추가 커널 4종 평가 | 30개 | 150개 중 144개 분석 | 다른 커널 특성에서의 추가 적용 결과 |

합성 배치 평가는 두 유형으로 구성하였다. 첫 번째는 작업 집합이 32 KiB인 저친화도 태스크가 총 이용률의 50%를 차지하는 경우이다. 두 번째는 작업 집합이 768 KiB인 태스크가 총 이용률의 25%를 차지하는 경우이다. 이하에서는 각각 32 KiB 유형과 768 KiB 유형으로 부른다. 나머지는 친화도가 높은 태스크로 구성하였다.

태스크 수는 집합마다 12–20개이며, 주기의 변동계수는 0과 0.2를 사용하였다. 32 KiB 유형의 코어당 부하는 0.45–0.60에서 0.025 간격으로 설정하였고, 768 KiB 유형은 0.30, 0.35, 0.40, 0.45를 사용하였다.

RF 평가에는 두 유형과 함께 L2 미스 이후 메모리 접근이 발생하는 유형을 추가하였다. 이 평가에서는 주기 변동계수를 0.2로 고정하고, 유형별 기본 태스크 집합 24개에 다섯 부하를 적용하였다. 후보 구성 중 하나라도 시작 시각 설정에 실패한 사례는 구성 간 비교에서 제외하였다. 이에 따라 합성 RF 평가에서는 357개, 미학습 커널 평가에서는 각각 118개와 144개의 사례를 분석하였다.

### 6.1.2 개발 자료와 평가 자료의 분리

친화도 배치 평가는 앞선 탐색에서 사용하지 않은 난수 시드로 태스크 집합을 생성하였다. CAAS 구성요소 비교에는 동일한 태스크 집합을 사용하여 배치 규칙만 바꾸었다. 따라서 두 평가는 같은 입력에서 방법을 비교하는 관계이며, 서로 독립적인 반복 실험은 아니다.

RF 모델은 개발 자료 11,733행으로 학습한 뒤 입력 특징, 확률 보정 방식 및 판정 임곗값을 고정하였다. 사용한 모델은 28개 특징과 isotonic 확률 보정을 적용한 RF v1이며, 실행을 허용하는 확률 임곗값은 \(\tau=0.8\)이다. 합성 RF 평가와 첫 번째 커널 평가에는 이 동결 모델을 적용하였다.

RF 개발 자료에는 친화도 배치 평가에 사용한 자료 일부가 포함된다. 그러므로 해당 자료는 배치 효과를 평가하는 데 사용하되, RF의 독립적인 예측 성능을 뒷받침하는 자료로 사용하지 않았다. RF의 평가는 새로 생성한 합성 태스크 집합과 학습에 포함되지 않은 커널 워크로드를 대상으로 수행하였다.

합성 RF 평가와 미학습 커널 7종 평가에서는 평가 대상인 공동 실행 전에 구성 선택 결과를 기록하고 고정하였다. 이후 커널 7종의 결과를 사용하여 학습 분포 밖 감지와 확률 재보정을 추가한 v2를 개발하고, 추가 커널 4종의 실험에 사전 등록하였다. 이 실험에서 v2가 마감을 지킬 수 있었던 47사례를 거절한 결과를 확인한 뒤, v1을 주 방법으로 유지하기로 하였다. v1의 결정도 같은 실험의 공동 실행 전에 저장되어 있었지만, v1을 최종 방법으로 유지한 선택에는 추가 커널의 결과가 관여하였다. 따라서 추가 커널 4종의 v1 결과는 독립적인 사전 등록 확증으로 제시하지 않고, 사전에 저장한 결정을 사후 분석한 결과로 구분한다. 정책 변경과 선택의 경위는 부록 D에 정리하였다.

가설과 분석 기준의 등록 시점도 구분하였다. 배치 평가의 TET 검정은 실행 도중 구성별 비교 결과를 확인하기 전에 추가한 항목이다. 실행 전에 등록한 항목과 동일하게 취급하지 않았으며, 추가 시점과 열람 범위는 부록 D에 기록하였다.

### 6.1.3 평가 지표와 통계 분석

마감 관련 주 지표는 한 번의 실행에서 모든 작업이 마감을 준수했는지 여부이다. 실행 전 점검의 결과는 선택한 구성의 마감 준수 여부와 거절한 사례에 실행 가능한 후보가 있었는지를 함께 사용하여 평가하였다.

실행시간은 TET와 TAT로 비교하였다. TET는 측정 구간에 실행한 작업의 CPU 시간 합이다. TAT는 예정 release 시각이 같은 작업들을 묶고, 각 묶음의 첫 시작부터 마지막 완료까지의 시간을 합한 값이다. 따라서 TAT는 개별 작업 응답시간의 합이나 전체 실행 구간의 길이와 구분된다.

저친화도 태스크의 실행시간 증가를 확인하기 위해 관측 최대 CPU 시간 증가 비율도 사용하였다. 이는 측정 구간에서 관측한 작업 CPU 시간을 해당 태스크의 계획 실행시간으로 나눈 뒤, 저친화도 태스크 중 최댓값을 취한 값이다. 이 값은 실험에서 관측한 증가 정도이며 WCET 상한을 의미하지 않는다. 6.5절의 커널별 사후 진단은 준비 구간을 포함한 기록을 사용하므로 이 지표와 관측 범위를 구분하였다.

배치 평가의 기존 판정에는 다음 지표도 사용되었다.

\[
\text{위반 지표}
=
\frac{\text{측정 구간의 늦은 작업 수}+\text{밀린 release 수}}
{\text{측정 구간에 예정된 작업 수}}.
\]

여기서 밀린 release는 앞선 작업의 지연 이후 측정 구간 안에서 release되지 못한 작업을 뜻한다. 실제 자료에서는 분자의 대부분이 밀린 release였다. 따라서 이 지표의 감소를 실제로 마감을 넘긴 작업의 비율 감소와 동일하게 해석하지 않았다. 본 장에서는 기존 가설의 판정 결과를 설명하는 보조 지표로 사용한다.

연속 지표는 같은 평가 사례에서 얻은 결과를 짝지어 비교하였다. TET, TAT 및 CPU 시간 증가 비율은 비교하는 두 배치가 모두 전체 마감을 준수한 사례를 대상으로 분석하였다. 백분율 효과는 사례별 로그 비의 중앙값을 원래 비율로 변환하여 계산하였다.

원분석에서는 Wilcoxon 부호순위 검정, 정확 McNemar 검정 및 Holm 보정을 사용하였다. TAT의 동등성은 허용 범위를 ±2%로 정하고, 로그 비에 대한 두 단측 부호순위 검정으로 평가하였다. AUC 차이의 원분석은 개별 평가 사례를 재표집하는 2,000회의 부트스트랩을 사용하였다.

동일한 기본 태스크 집합이 여러 부하에서 반복되므로, 사례 단위 분석을 보완하는 사후 분석도 수행하였다. 배치의 연속 지표는 기본 집합별 중앙 로그 비로 요약하였다. 합성 RF 평가의 AUC 비교는 유형별 기본 집합 24개를 각각 복원추출하고, 선택된 집합에 속한 유효 부하 사례를 함께 포함하는 층화 군집 부트스트랩을 사용하였다. 커널 평가에서는 기본 집합 24개를 같은 방식으로 재표집하였다. 두 분석 모두 난수 시드 20264400으로 2,000회 수행하고, 차이의 2.5·97.5백분위수를 신뢰구간으로 사용하였다. 이 보조 분석은 사전 등록 판정을 대체하지 않으며, 반복 자료의 의존성을 고려해 효과 방향이 유지되는지 확인하는 데 사용하였다.

## 6.2 캐시 친화도 기반 배치의 성능

### 6.2.1 CPU 시간과 TET

이하에서는 CHASER의 친화도 묶음·이용률 균형·release 고려를 결합한 배치를 RA-CGB로 표기한다. 비교 대상은 이용률 균형 배치인 WFD, 친화도 묶음과 이용률 균형을 결합한 CGB, 그리고 release를 고려한 배치인 RA이다. WFD와의 비교는 친화도 묶음과 release 고려를 함께 적용한 효과를 보여준다. RA와의 비교는 release를 고려하는 조건에서 친화도 묶음을 추가한 효과를 보여준다.

표 6.2는 두 배치가 모두 마감을 준수한 사례의 비교 결과이다. RA-CGB는 두 유형에서 관측 최대 CPU 시간 증가 비율과 TET를 모두 낮췄다. 관측 최대 CPU 시간 증가 비율은 기준 배치보다 15.2–20.0%, TET는 5.1–7.6% 감소하였다.

**표 6.2. 기준 배치 대비 RA-CGB의 실행시간 변화**

| 유형 | 기준 배치 | 양쪽 모두 마감을 준수한 사례 | 관측 최대 CPU 시간 증가 비율의 변화 | TET 변화 |
|---|---|---:|---:|---:|
| 32 KiB | RA | 122 | −15.2% | −6.3% |
| 32 KiB | WFD | 117 | −16.1% | −7.1% |
| 768 KiB | RA | 71 | −20.0% | −7.6% |
| 768 KiB | WFD | 70 | −17.5% | −5.1% |

원분석에서는 표의 두 지표에 대한 네 비교가 모두 Holm 보정 후 \(p<0.0001\)이었다. 기본 태스크 집합 단위로 다시 요약해도 감소 방향은 유지되었다. TET는 32 KiB 유형에서 RA 대비 18개 중 16개, WFD 대비 18개 중 17개 기본 집합에서 감소하였다. 768 KiB 유형에서는 비교 가능한 15개 기본 집합 중 각각 15개와 14개에서 감소하였다.

이 결과는 마감을 준수하는 실행 조건에서 친화도 묶음이 함께 실행할 때의 CPU 시간 증가를 줄였음을 보여준다. 다만 양쪽 배치가 모두 성공한 사례를 대상으로 얻은 결과이므로, 실패 사례까지 포함한 전체 워크로드의 실행시간 감소율로 확대해서 해석할 수는 없다.

그림 6.1과 그림 6.2는 네 배치가 모두 마감을 준수한 공통 사례에서 CPU 시간 증가 비율과 TET를 비교한다. 표 6.2는 두 배치별로 비교 가능한 사례를 사용하므로 그림과 표의 표본 범위가 다르다.

### 6.2.2 마감 준수와 위반 지표

그림 6.3과 그림 6.4는 부하와 주기 CV별 전체 마감 준수 사례 수를 보여준다. 실행시간의 감소가 전체 마감 준수 사례의 증가로 일관되게 이어지지는 않았다. 32 KiB 유형에서 모든 마감을 준수한 사례는 WFD 123개, RA 126개, RA-CGB 132개였다. 반면 768 KiB 유형에서는 각각 82개, 79개, 77개였다. RA-CGB와 두 기준 배치의 마감 준수 여부를 비교한 정확 McNemar 검정은 두 유형에서 모두 \(p>0.05\)였다.

기존 위반 지표에서는 WFD 대비 개선이 관측되었다. 한쪽 배치에서라도 위반 지표가 양수인 사례를 대상으로 비교하면, RA-CGB의 중앙 차이는 32 KiB 유형에서 −3.17%p, 768 KiB 유형에서 −4.13%p였다. 그러나 RA 대비 중앙 차이는 두 유형 모두 0이었다. 이에 따라 두 기준 배치 모두에 대해 위반 지표의 중앙값이 감소해야 한다는 사전 판정 조건은 충족하지 못하였다. 일부 검정의 p값이 작더라도 사전에 정한 효과 방향 조건까지 충족한 것은 아니다.

무작위 배치와의 보조 비교에서는 각 사례에서 얻은 세 무작위 배치의 위반 지표를 평균하여 기준값으로 사용하였다. RA-CGB와 세 무작위 배치 중 하나라도 위반 지표가 양수인 사례는 32 KiB 유형 231개, 768 KiB 유형 121개였다. 이 사례들에서 RA-CGB와 무작위 기준값의 중앙 차이는 각각 −9.8%p와 −11.7%p였다. 두 비교 모두 보조 가설군의 Holm 보정 후 유의하였다. 이는 늦은 작업과 밀린 release를 합친 지표의 차이이며, 전체 마감 준수율의 증가량을 뜻하지 않는다.

### 6.2.3 TAT의 유지 여부

친화도가 낮은 태스크를 묶으면 특정 코어에 작업이 집중되어 완료 시각이 늦어질 수 있다. 따라서 CPU 시간 감소와 함께 TAT가 유지되는지도 확인하였다.

32 KiB 유형에서 RA-CGB의 TAT는 RA 대비 약 0.4% 작았으며, ±2% 범위의 동등성 검정을 통과하였다. 기본 태스크 집합별 중앙 로그 비를 사용한 사후 분석에서도 같은 범위의 동등성이 유지되었다. 768 KiB 유형에서는 RA-CGB의 TAT가 RA보다 약 2.9% 컸고, 동등성 조건을 충족하지 못하였다. 기본 집합 단위 보조 분석에서도 이 판정은 달라지지 않았다.

친화도 묶음은 두 유형에서 CPU 시간과 TET를 줄였지만, RA 대비 TAT 유지까지 확인된 범위는 32 KiB 유형이었다. 큰 작업 집합을 가진 태스크의 묶음에서는 실행시간 감소와 완료 시각 사이의 상충 관계가 남았다.

그림 6.5는 네 배치가 모두 성공한 공통 사례의 TAT 분포를 보여준다. 본문의 효과 크기와 동등성 판정은 RA와 RA-CGB가 모두 성공한 사례별 짝 비교에서 얻었으며, 그림에 표시한 중앙값끼리 비교하여 판정한 결과는 아니다.

### 6.2.4 정적 L2 요청량 기준의 적용 범위

배치 평가에 사전 등록한 V1은 정적 L2 요청량 기준 \(D\)의 판정 결과를 확인하는 항목이다. \(D<0.9\)이면 성공, \(D\ge1.0\)이면 실패를 예측하고 그 사이는 판정을 유보하였다. 성공 예측의 정답은 WFD·CGB·RA·RA-CGB 네 배치가 모두 마감을 준수한 경우이며, 실패 예측의 정답은 네 배치 모두 실패한 경우로 정의하였다.

32 KiB 유형에서는 성공을 예측한 88개 사례와 실패를 예측한 84개 사례가 모두 이 조건을 충족하였다. 두 정확도의 단측 95% 이항 하한은 각각 약 96.7%와 96.5%로, 사전 판정 기준인 90%를 넘었다. 나머지 80개 사례는 중간 영역에 속하였다. 이 구간 또한 반복 사례를 독립 시행으로 취급한 원분석의 값으로 해석하였다.

적용 범위를 확인하기 위해 함께 보고한 768 KiB 유형에서는 성공을 예측한 유효 143개 사례 중 66개에서만 네 배치가 모두 마감을 준수하였다. 이 수치는 개별 실행의 성공률이 아니다. L2 요청량만으로 만든 기준은 큰 작업 집합을 포함한 조건의 성공 여부를 충분히 설명하지 못하였다. 이 결과는 제4장의 접근 계층 대조 및 제5장에서 메모리 수요를 함께 표현한 설계와 연결된다.

배치 평가에서 네 Partitioned 배치가 모두 실패한 사례는 32 KiB 유형 108개, 768 KiB 유형 53개였다. 이 중 Global이 마감을 준수한 사례는 각 유형에서 두 개였으며, 평가한 Clustered 구성에서는 없었다. 따라서 이 배치 평가에서도 G·C 대안의 유효 사례는 제한적이었다.

## 6.3 CAAS 대비 구성요소별 기여

### 6.3.1 비교 범위와 구성

CAAS와의 비교는 Partitioned 실행에서 사용하는 오프라인 태스크 배치 규칙을 대상으로 하였다. 제2장에서 설명한 CAAS의 캐시 친화도 지표와 Algorithm 1을 기준으로, 지표와 배치 절차를 단계적으로 변경하였다. 이 비교는 CAAS의 전체 스케줄링 구조 선택기를 재현하여 평가한 결과와는 구분된다.

비교 구성은 CA-CSRD와 Algorithm 1을 사용한 CAAS, 친화도 지표를 CLS로 변경한 CLS-A1, 개발 자료에서 보정한 CLS 임곗값을 적용한 보정 CLS-A1, 이용률 균형을 적용한 CGB, 그리고 release 고려를 추가한 RA-CGB이다. CAAS의 CA-CSRD 임곗값은 약 0.178로 동결하였고, CLS-A1의 임곗값은 0.5이며, 보정한 CLS 임곗값은 약 0.887이다.

Algorithm 1 계열은 한 코어를 격리 영역으로, 나머지 세 코어를 비격리 영역으로 사용하였다. 태스크가 해당 영역에 들어가지 못하더라도 다른 영역으로 넘겨 담지 않았다. 코어별 용량은 Algorithm 1 계열에서 1.0, CHASER 계열에서 0.95를 사용하였다. 배치 규칙이 태스크 집합을 수용하지 못한 경우는 배치 불가로 처리하였다. 실행 파일 생성을 위해 사용한 대체 배치는 해당 규칙의 유효한 결과로 인정하지 않았다.

### 6.3.2 친화도 지표와 묶음 방식의 영향

표 6.3은 각 구성에서 배치가 가능하고 실행 시작에 성공한 사례 수와, 그중 모든 마감을 준수한 사례 수를 나타낸다.

|---|---:|---:|

32 KiB 유형에서는 CAAS와 CLS-A1의 결과가 같았다. 두 구성 모두 252개 사례 중 77개만 배치할 수 있었으며, 모든 마감을 준수한 사례는 한 개였다. 친화도 지표를 CLS로 바꾸는 것만으로는 고정된 격리 영역에 태스크가 몰리는 문제를 해결하지 못하였다.

이용률을 고려하여 묶음을 구성한 CGB는 252개 사례를 모두 배치하였고, 그중 136개에서 모든 마감을 준수하였다. CLS-A1과의 짝 비교에서는 CGB만 배치와 마감 준수에 성공한 사례가 135개였으며, 반대 사례는 없었다. 이 조건에서는 친화도 값의 변경보다 묶음의 크기와 이용률 분산 방식이 결과에 더 큰 영향을 주었다.

768 KiB 유형에서는 같은 개선이 나타나지 않았다. CAAS도 모든 사례를 배치할 수 있었고, 전체 마감 준수 사례는 CAAS 84개와 RA-CGB 77개였다. 짝 비교에서 CAAS만 준수한 사례는 9개, RA-CGB만 준수한 사례는 2개였으며, 보조 분석의 Holm 보정 p값은 0.523이었다. 따라서 관측된 사례 수의 차이만으로 CAAS의 마감 준수 성능이 더 높다고 결론 내릴 수는 없다.

그림 6.6은 Algorithm 1 계열의 결과를 부하별로 나누어 보여준다. 막대에는 표 6.3과 마찬가지로 배치가 가능하고 실행 시작에도 성공한 사례만 포함한다.

### 6.3.3 Release 고려와 통합 배치의 효과

CGB에 release 고려를 추가한 RA-CGB는 양쪽 배치가 모두 마감을 준수한 사례에서 TAT를 줄였다. 감소율은 32 KiB 유형에서 약 0.69%, 768 KiB 유형에서 약 0.13%였다. 원분석의 Holm 보정 p값은 각각 \(8.89\times10^{-8}\)과 0.037이었다. 효과의 크기는 작았으며, 앞 절에서 확인한 RA 대비 TAT 증가를 모든 유형에서 해소하는 수준은 아니었다.

CAAS와 RA-CGB의 직접 비교에서도 지표별 결과가 달랐다. 32 KiB 유형에서는 기존 위반 지표가 감소했지만, 두 배치가 모두 마감을 준수한 사례가 한 개뿐이어서 일반적인 TET 개선율을 제시하기 어려웠다. 768 KiB 유형에서는 양쪽 모두 마감을 준수한 75개 사례에서 관측 최대 CPU 시간 증가 비율이 약 8.6%, TET가 약 2.8% 감소하였다. 그러나 전체 마감 준수 사례 수의 증가가 확인되지는 않았다.

이 비교는 친화도 지표, 묶음 방식 및 release 고려가 서로 다른 역할을 수행함을 보여준다. 특히 저친화도 태스크의 이용률 비중이 큰 조건에서는 고정된 한 코어에 격리하는 방식의 제약이 컸다. 반면 그러한 배치 제약이 작은 조건에서는 CPU 시간 감소가 전체 마감 준수 개선으로 이어지지 않았다.

## 6.4 실행 전 점검의 효과

### 6.4.1 마감 준수 예측력

실행 전 점검은 동결 RF, 정적 \(D+M\) 규칙 및 점검 없이 항상 RA-CGB를 실행하는 방법으로 비교하였다. 정적 규칙은 \(D+M<0.975\)이면 RA-CGB의 실행을 허용한다. 이 임곗값은 개발 자료에서 정한 뒤 평가 전에 고정하였다.

예측력 비교에는 RF의 Partitioned 후보 마감 준수 확률과 정적 점수 \(-D\), \(-(D+M)\)를 사용하였다. 따라서 AUC는 최종 P·G·C 선택 결과가 아니라, RA-CGB가 마감을 준수할지를 구분하는 능력을 나타낸다.

유효한 357개 사례에서 RF의 AUC는 0.982였으며, \(D\)는 0.746, \(D+M\)은 0.960이었다. RF와 \(D\)의 AUC 차이는 0.236이었다. 같은 기본 집합의 반복 부하를 함께 재표집하고 유형별 집합 수를 유지한 사후 분석에서 차이의 95% 신뢰구간은 \([0.201,\,0.274]\)였다. RF와 \(D+M\)의 차이는 0.022였고, 같은 방식의 신뢰구간은 \([0.011,\,0.036]\)이었다.

두 비교 모두 기본 집합 단위 분석에서 양의 차이가 유지되었다. 다만 \(D\) 대비 차이보다 \(D+M\) 대비 차이가 작다는 점은 메모리 수요를 함께 표현하는 것 자체가 예측력 향상에 상당한 역할을 했음을 보여준다.

### 6.4.2 실행 허용과 거절

실행 여부와 구성 결정은 네 결과로 구분하였다. 실행을 허용한 경우에는 선택한 구성이 모든 마감을 준수했는지를 확인하였다. 거절한 경우에는 평가한 네 후보 중 마감을 준수한 구성이 있었는지를 확인하였다. 여기서 불필요한 거절은 평가한 네 후보 중 하나 이상이 성공했는데 실행을 거절한 경우를 뜻한다.

**표 6.4. 합성 워크로드에서 실행 전 점검의 결정 결과**

| 방법 | 실행 허용 후 마감 준수 | 실행 허용 후 마감 위반 | 가능한 후보가 있었으나 거절 | 네 후보 모두 실패하여 거절 |
|---|---:|---:|---:|---:|
| RF | 191 | 2 | 69 | 95 |
| 정적 D+M 규칙 | 157 | 5 | 100 | 95 |
| 항상 RA-CGB 실행 | 218 | 139 | 0 | 0 |

RF는 193개 사례의 실행을 허용하였으며, 그중 두 사례가 마감을 위반하였다. 실행을 허용한 사례 중 위반 비율은 1.04%였고, 독립 이항모형으로 계산한 단측 95% Clopper–Pearson 상한은 3.23%였다. 이는 관측 위반 비율 2% 이하와 상한 5% 이하라는 사전 판정 기준을 충족하였다. 다만 이 상한은 반복 부하에 따른 의존성을 보정한 운용 실패확률의 보장이 아니다.

정적 규칙과 비교하면 RF는 실행을 허용하고 실제로 마감을 준수한 사례를 34개 더 확보하였다. 짝 비교에서 RF만 성공한 사례는 35개, 정적 규칙만 성공한 사례는 한 개였다. 원분석의 정확 McNemar 검정 결과는 \(p=1.08\times10^{-9}\)였다.

기본 집합 단위 보조 분석에서도 같은 방향이 나타났다. RF의 성공 사례 수가 더 많은 기본 집합은 32개, 정적 규칙이 더 많은 집합은 한 개, 동률은 39개였으며, 비동률 집합에 대한 정확 부호검정은 \(p=7.92\times10^{-9}\)였다.

이 결과에서 RF는 정적 규칙보다 실행 후 마감을 준수한 사례를 더 많이 확보하였고, 관측된 잘못 허용 건수도 적었다. 다만 두 방법의 실패율에 대한 동등성이나 비열등성을 검정한 것은 아니므로 동일한 안전성을 입증했다고 해석하지 않았다.

### 6.4.3 Global·Clustered 전환

RF는 183개 사례에서 Partitioned를 선택하고, 10개 사례에서 Global 또는 Clustered를 선택하였다. 나머지 164개는 거절하였으며 보류 사례는 없었다.

전환한 구성은 Global 7개, Clustered 1+3 두 개, Clustered 1+1+2 한 개였고 모두 마감을 준수하였다. 그러나 이 중 여덟 사례는 RA-CGB도 성공하였다. RA-CGB가 실패하고 전환한 구성만 성공한 사례는 두 개였다.

반대 방향의 실패는 관측되지 않았지만 개선 사례가 두 개에 그쳐 정확 양측 검정 결과는 \(p=0.5\)였다. 따라서 이 자료는 G·C 전환으로 실패를 피한 사례가 존재함을 보여주지만, 전환의 일반적인 효과를 확증하기에는 부족하다.

또한 이 평가의 유효 사례는 모두 단독 실행 기준으로 Partitioned 배치가 가능한 범위에 속했다. 따라서 큰 태스크의 조합 때문에 Partitioned 배치 자체가 불가능한 영역에서 G·C 대안을 선택하는 능력은 별도의 평가 대상으로 남는다.

## 6.5 학습에 쓰지 않은 커널 워크로드

### 6.5.1 커널 구성과 적용 범위

새로운 프로그램에서의 적용 결과는 PolyBench 기반 수치 계산 커널을 사용하여 평가하였다. 첫 번째 평가는 GEMM, ATAX, BICG, MVT, GESUMMV, Jacobi-1D 및 Jacobi-2D의 일곱 커널로 구성하였다. 추가 평가는 2MM, SYRK, TRMM 및 DOITGEN의 네 커널을 사용하였다. PolyBench의 반복문 중심 커널을 RTEMS 실행과 분석 조건에 맞게 정수형으로 변형하였으므로, 원본 벤치마크의 표준 성능 비교나 실제 탑재 소프트웨어의 검증 결과와는 구분된다.

커널별 배열 크기와 반복 횟수를 정한 뒤 해당 조건의 단독 실행시간을 측정하여 계획 이용률을 구성하였다. 두 평가 모두 코어당 부하 0.40, 0.475, 0.55, 0.625, 0.70을 사용하였다.

두 커널 집합에는 CLS가 0.5 이하인 태스크가 없었다. 따라서 이 평가는 저친화도 태스크를 묶는 동작을 직접 검증하는 자료는 아니다. 해당 조건에서 RA-CGB는 이용률 균형 배치에서 출발하여 release를 고려하였으며, 동결 RF로 실행 여부를 결정하였다.

### 6.5.2 미학습 커널 7종의 결과

유효한 118개 사례에서 RF의 AUC는 0.981, D는 0.901, D+M은 0.973이었다. 기본 집합 단위로 반복 부하를 함께 재표집한 사후 분석에서 RF와 D의 AUC 차이에 대한 95% 신뢰구간은 \([0.033,\,0.135]\)였다. 반면 RF와 D+M의 차이는 \([-0.008,\,0.023]\)으로 0을 포함하였다. 따라서 이 커널 자료에서는 RF가 D보다 우수하다는 결과는 유지되었지만, D+M보다 우수하다고 주장할 근거는 충분하지 않았다.

실행 여부의 결정은 AUC와 다른 양상을 보였다. RF는 112개 사례를 허용하였으며, 96개가 마감을 준수하고 16개가 위반하였다. 실행을 허용한 사례 중 위반 비율은 14.29%였고, 단측 95% 이항 상한은 20.89%였다. 이는 사전에 정한 허용 후 위반 기준을 충족하지 못하였다.

### 6.5.3 예측 순위와 확률 보정의 차이

높은 AUC가 고정 임곗값에서의 정확한 실행 허용으로 이어지지 않은 양상을 살펴보기 위해 예측 확률 구간별 결과를 사후 분석하였다. 그림 6.10은 합성 워크로드와 미학습 커널의 구간별 실제 마감 준수 비율을 비교한다.

커널 7종 평가에서 Partitioned 후보의 예측 확률이 0.95 이상인 90개 사례는 모두 마감을 준수하였다. 그러나 예측 확률이 0.8 이상 0.95 미만인 22개 사례 중 실제로 마감을 준수한 것은 여섯 개였다. 합성 평가의 같은 확률 구간에서는 45개 중 43개가 마감을 준수하였다.

이 차이는 합성 자료에서 얻은 확률의 해석이 새로운 커널에서도 유지되지 않았음을 보여준다. RF는 성공과 실패를 상대적으로 구분하는 순위에서는 높은 성능을 보였지만, 실행을 허용하는 임곗값 부근에서 준수 확률을 과대평가하였다.

이 결과를 바탕으로 별도의 v2를 개발하였으나, 본 절의 수치는 처음 동결한 v1의 결과이다. v2를 개발한 사실과 추가 평가 이후 v1을 유지한 선택은 다음 절과 부록 D에 함께 보고한다. 따라서 평가 결과를 확인한 이후 어떠한 모델 변경도 시도하지 않았다고 해석해서는 안 된다.

> **그림 6.10. 예측 확률과 실제 마감 준수 빈도의 관계.** 동결 RF v1 출력에 대한 사후 진단이다. 같은 확률 구간에 속한 사례들의 RA-CGB 실제 준수 비율을 표시하였다. 막대 위 숫자는 준수 사례 수 / 구간의 사례 수이며, 표본이 없는 구간은 0%와 구분하였다. 각 구간은 하한을 포함하고 상한을 제외하되 마지막 구간은 확률 1을 포함한다. 점선은 실행 허용 임곗값 \(\tau=0.8\)이다. 이 그림은 v2 재보정 결과가 아니다.

### 6.5.4 추가 커널 4종과 정책 선택의 경위

추가 커널 4종의 유효한 144개 사례에서는 v1이 모두 Partitioned로 실행하도록 결정하였으며 모두 마감을 준수하였다. 정적 규칙과 항상 RA-CGB를 실행하는 방법도 같은 결과를 보였다.

당시 사전 등록한 주 정책인 v2는 97개 사례의 실행을 허용하고 47개를 거절하였다. 거절한 47개는 모두 RA-CGB를 포함한 네 후보가 실제로 마감을 준수한 사례였다. 따라서 이 자료에서 v2의 결과는 실행 허용 후 준수 97개, 잘못 허용 0개, 불필요한 거절 47개였다. v2는 학습 분포 밖 감지와 커널 7종 자료를 이용한 확률 재보정을 함께 추가한 정책이므로, 두 변경의 영향을 개별적으로 분리한 결과는 아니다.

이 결과를 확인한 뒤 v1을 주 방법으로 유지하였다. v1과 v2의 결정 자체는 실행 전에 기록되어 있었지만, 최종 정책의 선택은 결과 확인 이후에 이루어졌다. 따라서 추가 커널의 v1 결과에는 이러한 선택 경위를 함께 고려해야 한다.

v1이 잘못 허용한 사례는 없었고, 독립 이항모형으로 계산한 단측 95% 상한은 약 2.1%였다. 그러나 모든 사례가 성공한 자료이므로 AUC를 계산할 수 없으며, 실패 사례를 구분하는 능력이나 두 정책의 안전성 우열을 평가한 결과로 해석할 수 없다.

### 6.5.5 접근 특성과 작업 CPU 시간의 사후 진단

두 커널 집합의 접근 특성은 달랐다. 커널 7종의 CLS 중앙값은 0.971이고 단독 실행시간으로 정규화한 L2 요청률 중앙값은 약 2.08회/µs였다. 추가 커널 4종에서는 각각 0.998과 약 0.10회/µs였다. 여기서 요청률은 HARA가 추정한 작업별 L1 미스 수를 계획 단독 실행시간으로 나눈 값이며, 동시 실행 중 측정한 시스템 전체 요청률은 아니다. 그림 6.11은 이 요청률의 분포를 합성 유형별·커널별로 나누어 보여준다.

> **[그림 6.11 삽입 위치]**
>
> 그림 내용: 합성 워크로드 세 유형과 두 커널 집합의 태스크별 L1 미스 요청률 분포를 로그 눈금의 상자그림으로 표시한다.
>
> **그림 6.11. 평가 워크로드별 단독 실행 기준 L1 미스 요청률 분포.** 요청률은 HARA가 모델링한 작업의 L1 미스 수를 계획 단독 실행시간으로 나눈 값이다. 상자는 25–75백분위수, 수염은 5–95백분위수이며, 굵은 선과 숫자는 중앙값이다. 세로축은 로그 눈금이다. 입력 특성을 비교한 그림이므로 커널 자료에는 시작 실패로 마감 평가에서 제외한 사례의 입력도 포함되며, 태스크 관측은 부하별로 반복 집계된다. 동시 실행 중 실측한 공유 L2 요청률을 의미하지 않는다.

고부하 두 조건인 0.625와 0.70에서는 작업 CPU 시간의 증가도 사후에 살펴보았다. 각 태스크에 대해 준비 구간을 포함한 기록된 작업 중 최대 CPU 시간을 계획 단독 실행시간으로 나누고, 그 비율을 커널별로 요약하였다. 그림 6.12에서 커널 7종 중 GEMM을 제외한 여섯 커널의 중앙값은 1.31–1.82배였으며, GEMM은 1.04배였다. 추가 커널 4종의 중앙값은 모두 약 1.02배였다.

이 통계는 커널 7종에서 함께 실행할 때의 CPU 시간 증가가 관측되었음을 보여준다. 다만 마감 실패 이후 작업 기록의 범위가 달라지며, 커널 7종의 태스크 관측 731개 중 89개에는 준비 구간 이후 작업 기록이 없었다. 따라서 이를 측정 구간 전체의 작업 최대시간이나 실패 원인의 직접적인 측정으로 해석하지 않았다. 제4장에서 다룬 계획 이용률과 실제 CPU 시간의 차이를 새로운 커널에서도 점검하는 사후 진단으로 사용하였다.

> **[그림 6.12 삽입 위치]**
>
> 그림 내용: 부하 0.625와 0.70에서 기록된 태스크별 최대 작업 CPU 시간 / 계획 실행시간의 분포를 커널별 상자그림으로 표시한다.
>
> **그림 6.12. 고부하에서 관측한 커널별 작업 CPU 시간 증가 비율.** 부하 0.625와 0.70에서 네 후보의 결과가 모두 판정 가능한 사례를 대상으로 하였다. 값은 RA-CGB에서 각 태스크의 준비 구간을 포함한 기록된 작업 중 최대 CPU 시간을 계획 단독 실행시간으로 나눈 비율이다. 커널 7종은 47개 평가 사례·731개 태스크 관측, 추가 커널 4종은 55개 평가 사례·862개 태스크 관측을 포함한다. 상자는 25–75백분위수, 수염은 5–95백분위수이며, 굵은 선과 상단 숫자는 중앙값이다. 이름 옆 괄호는 태스크 관측 수, 점선은 비율 1이다. 동일한 기본 집합은 부하별로 반복 포함되며, 수염은 신뢰구간이 아니다. 마감 실패 시 태스크가 이후 작업을 실행하지 않는 동작을 고려한 사후 진단이다.

추가 커널 평가의 전부 성공 결과가 앞선 고부하 실패를 해소한 것은 아니다. 두 결과는 서로 다른 접근 특성에서 동일한 v1 모델이 보인 적용 결과이며, v2에서 관측된 불필요한 거절까지 함께 고려해야 한다.

## 6.6 분석·결정 비용

CHASER의 결정 시간은 입력 자료와 동결 모델을 메모리에 읽은 이후, 후보 배치 생성부터 특징 계산과 RF 추론을 거쳐 최종 구성을 결정하기까지의 호스트 경과시간으로 측정하였다. 이 구간에는 HARA 분석, 실행 파일 빌드, 단독 실행시간 측정 및 모델 로딩은 포함되지 않는다.

**표 6.6. RF v1의 실행 전 결정 시간**

| 평가 자료 | 분석 사례 | 중앙값 | 최댓값 |
|---|---:|---:|---:|
| 합성 RF 평가 | 357 | 0.443초 | 0.661초 |
| 미학습 커널 7종 | 118 | 0.477초 | 0.682초 |
| 추가 커널 4종 | 144 | 별도 기록 없음 | 별도 기록 없음 |

추가 커널 실험의 기록에 남은 중앙값 0.58초와 최댓값 0.79초는 당시 주 정책인 v2를 측정한 값이다. 함께 실행한 비교 정책 v1에는 별도의 타이머를 적용하지 않았으므로 이 값을 v1의 비용 표에 포함하지 않았다.

저장된 동결 v1 모델은 확률 보정을 위한 다섯 RF로 구성되며, 각 RF는 500개의 트리를 포함한다. 전체 트리 수는 2,500개이고 직렬화한 모델 파일의 크기는 약 66.9 MB이다. 이 파일 크기는 실행 중 최대 메모리 사용량을 의미하지 않는다.

커널 7종 평가의 120개 설계 사례를 사후 재측정한 기록에는 HARA 분석 시간이 사례당 중앙값 1.76초, 최댓값 2.33초로 남아 있다. 다만 반복별 원시 시간과 호스트 조건이 충분히 보존되어 있지 않아 참고값으로 한정하였다. 별도로 측정한 분석 시간과 결정 시간의 중앙값을 더하여 전체 처리시간의 실측값으로 제시하지 않았다.

표 6.6의 시간은 오프라인 호스트에서 측정한 비용이다. RTEMS 작업의 실행시간이나 GR740에서의 온라인 스케줄러 부하로 해석할 수는 없다. 또한 CAAS와 동일한 조건에서 전체 분석 과정을 직접 비교한 비용 평가는 수행하지 않았으므로 분석 비용의 상대적 우위는 본 평가의 주장 범위에 포함하지 않는다.

## 6.7 한계 및 타당성 위협

실험 결과는 laysim의 GR740 모델과 RTEMS 실행 환경에 한정된다. 실제 GR740 보드의 메모리 시스템, 인터럽트 및 운영 환경에서도 같은 효과가 나타나는지는 별도의 검증이 필요하다. 본 장에서 보고한 것은 접근 특성을 통제한 조건의 실행 결과와 CPU 시간 변화이며, 공유 자원 경합을 하드웨어 성능 카운터로 직접 측정한 결과는 아니다.

마감 준수는 정해진 실행 구간에서 관측한 결과이다. 관측 최대 CPU 시간 역시 해당 구간에 실행한 작업들의 최댓값이므로 모든 입력과 실행 상태에 대한 WCET 또는 스케줄 가능성의 증명으로 사용할 수 없다. 특히 작업이 지연된 뒤 release가 밀리는 실행 동작 때문에 기존 위반 지표는 실제로 늦게 완료한 작업 수와 구분하여 해석해야 한다. 커널의 CPU 시간 진단은 준비 구간을 포함한 기록을 사용하므로 배치 평가의 측정 구간 통계와 직접 합치지 않았다.

평가 자료에는 같은 기본 태스크 집합을 여러 부하와 주기 조건에서 반복한 구조가 있다. 원분석의 사례 단위 검정과 이항 신뢰구간은 이 의존성을 모두 반영하지 못한다. 기본 집합 단위 보조 분석에서 주요 실행시간 개선과 AUC 차이는 유지되었지만, 위반 지표의 효과는 집계 방식에 더 민감하였다. 표본 수 또한 사전 검정력 계산으로 정한 것은 아니므로 작은 차이나 드문 전환 효과에 대한 비유의 결과를 동등성의 근거로 사용하지 않았다.

실행시간 비교는 양쪽 배치가 모두 마감을 준수한 사례에 조건부로 수행하였다. 이 방식은 실패 실행에서 작업 수가 달라지는 문제를 피하지만 비교 가능한 사례가 제한된다. 따라서 실행시간 개선과 전체 마감 준수 결과를 함께 제시하였다. CAAS 비교도 고정 Partitioned 배치 규칙을 대상으로 하였으므로 전체 CAAS 프레임워크에 대한 우열을 의미하지 않는다.

실행 전 점검의 일반화에는 한계가 나타났다. 합성 워크로드에서는 사전에 정한 판정 기준을 충족했지만, 미학습 커널의 높은 부하에서는 준수 확률을 과대평가하였다. 이를 바탕으로 시험한 v2는 재보정에 사용하지 않은 추가 커널 집합에서 마감을 준수할 수 있었던 47사례를 거절하였다. 시험한 분포 밖 감지와 확률 재보정의 조합은 이 추가 자료에서 불필요한 거절을 늘렸으며, 새로운 커널에 대한 개선 효과를 확인하지 못하였다. 또한 추가 커널 결과를 확인한 뒤 v1을 유지한 선택이 이루어졌으므로 그 자료를 최종 정책의 독립 확증으로 사용할 수 없다. 커널 평가에 저친화도 태스크가 없었다는 점도 새로운 실제 커널에서 친화도 묶음 자체의 효과를 판단하는 데 제약이 된다.

재현성은 일부 사례를 다시 빌드하고 실행하여 점검하였다. 배치 평가, CAAS 비교, 메모리 접근 대조 및 합성 RF 평가에서 총 8개 평가 사례의 20개 실행을 선정하였다. 변동하는 실행 메타데이터를 제외한 비교에서 작업별 시각·응답·마감 판정 등은 모두 재현되었으며, 실행 파일과 로그의 해시는 달랐다. 원본 실행 파일이 남아 있던 비교 대상 32개는 디버그 정보를 제거한 뒤 일치하였다. 이는 선정한 표본의 재현 점검이며 전체 실험의 모든 사례를 재실행한 결과는 아니다. 점검 대상과 비교 범위는 부록 A에 기록하였다.

G·C 전환으로 Partitioned의 실패를 피한 사례는 확인되었으나 그 수가 적었다. 현재 평가만으로는 전환의 일반적인 효과나 Partitioned 배치 불가 영역에서의 선택 성능을 확증하기 어렵다. 후속 평가에서는 해당 영역의 태스크 집합과 실패 경계에 가까운 미학습 커널을 확보하고, 모델과 판정 기준을 고정한 상태에서 검증할 필요가 있다.
