# Feature 사전 점검 — 끝난 실험 결과로 입력 표현 비교

새 시뮬레이션 없이 실험 5–9의 결과 묶음(`results/`)을 다시 분석한다.

## 개요

데이터셋 명세의 RF 입력(R0: CLS 통계 + U 통계 11개)과 이를 넓힌 표현들을 같은 RF로 학습해 비교한다.
- 실행 전에 알 수 있는 정적 정보만 feature로 쓴다.
- 판단 대상은 끝난 실험의 측정 TAT로 정한 "더 나은 배치·아키텍처"다.

## 목적

1. R0가 실험에서 찾은 메커니즘(트래픽, 작업 집합 크기, 큰 task, 주기)을 구분하지 못하는 사례가 실제로 있는지 확인한다.
   있다면 넓힌 표현이 그 사례를 구분하는지 본다.
2. 배치 정책(P-first 구조)과 아키텍처 선택에서 표현을 넓히면 TAT regret이 줄어드는지 본다.
3. RF 학습 방식(하드 레이블, 손해 가중치, 회귀형)의 차이를 본다.

이 결과는 설계된 셀에서 나온 것이므로 일반화 근거가 아니다.
"feature가 알려진 메커니즘을 담는가"를 확인하는 용도다.

## 변인

| 구분 | 내용 |
|---|---|
| 조작 변인 | 입력 표현 6종(아래 표), 학습 방식 3종(하드 레이블 / 손해 가중치 / 회귀형), 교차 검증 2종(set 단위 / 조건 단위) |
| 통제 변인 | 같은 표본·레이블·RF 설정(트리 100개, 깊이 제한 없음, max_features sqrt, 잎 최소 1; 계획의 기준 설정, 튜닝 없음), seed 42–46 |
| 종속 변인 | 고른 선택지의 TAT regret(고른 TAT ÷ 최선 TAT − 1)의 평균·95백분위·최대, 정확도(전체, 1·2위 차이 1% 이상인 set), deadline을 놓친 선택 수 |

**입력 표현**(모두 task 수와 무관한 고정 길이):

| 이름 | 구성 | 차원 |
|---|---|---:|
| R0 | 계획의 CLS+U: CLS 평균·표준편차·최소·최대·중앙값 + U 같은 5개 + U 합 | 11 |
| R0-CLP | 계획의 CLP+U: CLP 세 성분 각 5개 통계 + U 6개 | 21 |
| R1 | R0 + 주기 5개 통계 + 주기 CV | 17 |
| R2 | R1 + 트래픽·작업 집합 각 5개 통계 + task set 단위 값 9개 | 36 |
| R3 | R1 + task 유형 bag-of-words(유형별 U 합 12 + 개수 12) + task 수 | 42 |
| R4 | R2 + task 유형 bag-of-words | 60 |

task별 값:
- **U:** 단독 실행 CPU ÷ 주기. 실험 9는 설계 U를 쓴다.
- **CLS·CLP:** yarda cold job 분석.
- **트래픽:** job당 L1 miss ÷ job 자신의 CPU 시간(µs).
- **작업 집합:** yarda `memory` × 32 B. L2보다 작으면 cold job이 건드리는 서로 다른 cache line 크기와 같다.
- **실험 9:** yarda 분석이 없어 cyclic 64줄(2 KiB)의 닫힌 형식으로 계산한다. 첫 sweep만 miss이고 나머지는 L1 hit이다.

R2의 task set 단위 값은 다음 9개다.
- task 수, 코어당 task 수
- U 가중 평균 CLS
- 전체 트래픽 ÷ L2 처리 능력(48 ns마다 요청 1개, 1 µs에 약 20.8개)
- 가장 큰 작업 집합 4개의 합 ÷ L2(2 MiB)
- U > 0.5인 task 수
- 동시 release 부하(0 ms에 release되는 작업량 ÷ (코어 수 × 최소 주기)), 서로 다른 주기 수, 주기 쌍 중 배수 관계 비율

**task 유형(bag-of-words의 단어)** 은 하드웨어 기준 3 × 2 × 2 = 12가지다.
- **작업 집합:** 16 KiB(L1) 이하 / 512 KiB(L2를 코어 4개가 나눈 몫) 이하 / 초과
- **트래픽:** 1 µs당 5.2개(L2 처리 능력의 1/4) 이하 / 초과
- **U:** 0.5 이하 / 초과
- 경계값은 낮은 쪽 구간에 넣는다.

## 판단 대상(레이블)

모든 레이블은 측정 TAT가 가장 작은 선택지다. TAT가 정확히 같으면 TET를 보고, 그래도 같으면 첫 선택지를 고른다.

| 이름 | 선택지 | 표본 |
|---|---|---|
| placement | Partitioned 섞음 / 묶음 | 실험 5(트래픽 그대로·맞춤, 낮은 CLS 4·8·12개), 6(주기 80·30·20 ms), 7(task U CV 0.25·0.5·0.75), 8(SL·BL·SH·BH) |
| hl-policy | Partitioned WFD / 정보 기반 | 실험 9 |
| hl-family | Partitioned(WFD·정보 기반 중 나은 쪽) / Clustered((1+3)·(1+1+2)·정보 기반 중 나은 쪽) / Global | 실험 9. deadline을 놓친 구성은 쓸 수 없는 선택지로 둔다. |

placement 표본 구성 규칙:
- 두 배치가 모두 정상 실행된 set만 쓴다.
- 실험 6의 40 ms와 실험 7의 U CV 0은 실험 5의 set과 같은 실행이므로 뺀다.
- 실험 5의 낮은 CLS 0·16개는 묶음 배치가 정의되지 않으므로 표본에서 빠진다.

## 방법

1. 결과 묶음의 `results*.jsonl`과 `per-set.jsonl.gz`에서 set별 task 값을 만든다.
   - 결과 행의 CLS·L1 miss가 yarda 분석값과 같은지 확인한다.
2. 학습 방식은 세 가지다.
   - **하드 레이블:** RF 분류기
   - **손해 가중치:** 분류기에 "틀렸을 때의 손해"(1·2위 차이, 최대 1)를 표본 가중치로 준다.
   - **회귀형:** RF 회귀기로 선택지마다 regret을 예측하고 가장 작은 것을 고른다. deadline을 놓친 선택지의 regret은 1로 둔다.
3. 교차 검증은 두 가지다.
   - **set 단위:** set 번호로 10겹을 나눈다(GroupKFold). 실험들이 같은 set 번호에 같은 난수를 쓰므로 번호 단위로 묶는다.
     본 조건의 새 task set을 맞히는지 본다.
   - **조건 단위:** 조건 하나씩을 학습에서 통째로 뺀다. 학습에 없던 조건을 맞히는지 본다.
4. 기준선은 세 가지다.
   - 항상 같은 선택지
   - 학습 fold에서 평균 regret이 가장 작았던 고정 선택지
   - 측정상 최선(oracle)
5. **충돌 점검:** feature를 0–1로 정규화했을 때 모든 차원이 1% 이내로 같은 set 쌍을 찾는다.
   그중 레이블이 다르고 두 set 모두 1·2위 차이가 1% 이상인 쌍을 센다.
   - 실험 5의 "트래픽 그대로 대 맞춤"(같은 p·CV·set)과 실험 8의 "SH 대 BH", "SL 대 BL"(같은 set)은 따로 센다.

## 결과

표의 regret은 고른 선택지의 TAT가 측정상 최선보다 몇 % 긴지의 평균이다. 0%가 최선이다. RF 수치는 seed 5개의 평균이다.

### 1. R0가 구분하지 못하는 사례(충돌 점검, placement 677 set)

| 표현 | 거의 같은 쌍 | 레이블이 다른 쌍 | 실험 5 그대로 대 맞춤(238쌍) | 실험 8 SH 대 BH(20쌍) |
|---|---:|---:|---:|---:|
| R0 (CLS+U) | 2,779 | 809 | 238쌍 모두 거의 같음 | 20쌍 모두 거의 같음 |
| R1 (R0 + 주기) | 2,779 | 809 | 238 | 20 |
| R0-CLP (CLP+U) | 1,200 | 104 | 0 | 0 |
| R2 | 1,140 | 98 | 0 | 0 |
| R3 (bag-of-words) | 1,276 | 109 | 0 | 0 |
| R4 | 1,140 | 98 | 0 | 0 |

"레이블이 다른 쌍"은 거의 같은 쌍 중에서 레이블이 다르고, 두 set 모두 1·2위 차이가 1% 이상인 쌍이다.
- **R0:** 충돌 809쌍 중 690쌍이 실험 5의 그대로 대 맞춤이다(p = 0.5에서 441쌍, 0.25에서 232쌍, 0.75에서 17쌍). 실험 8의 SH 대 BH도 9쌍이다.
- **넓힌 표현:** 남은 98쌍(R2·R4)은 모두 feature가 완전히 같은 쌍이다. 실험 5의 CV 0 set끼리(p = 0.25)로, 낮은 CLS task의 위치(task 번호)만 다르다. task 순서를 버리는 어떤 집합 표현으로도 구분할 수 없는 쌍이다.

### 2. Partitioned 묶음 대 섞음(placement)

평균 regret을 "분류기 / 회귀형" 순서로 적었다.

| 방법 | 새 task set(set 단위) | 학습에 없던 조건(조건 단위) |
|---|---:|---:|
| 항상 섞음 | 2.73% | 2.73% |
| 항상 묶음(학습 fold 최선 고정과 같음) | 1.02% | 1.02% |
| R0 | 0.52% / 0.52% | 1.81% / 1.66% |
| R1 | 0.52% / 0.52% | 1.79% / 1.64% |
| R0-CLP | 0.28% / 0.27% | 0.95% / 0.94% |
| R2 | 0.28% / 0.27% | 0.40% / 0.49% |
| R3 | 0.29% / 0.26% | 0.90% / 0.74% |
| R4 | 0.28% / 0.27% | 0.47% / 0.36% |

손해 가중치 분류기는 하드 레이블 분류기와 거의 같았다.

조건 단위에서 차이가 난 조건(분류기 regret):
- **트래픽 맞춤, 낮은 CLS 8개(섞음이 나은 조건):** R0 3.08%는 "항상 묶음"과 같다. 같은 R0 값을 가진 트래픽 그대로 set이 학습에 있어서 묶음을 고른다. R0-CLP는 2.20%, R2는 0.26%, R4는 0.25%다.
- **트래픽 그대로, 낮은 CLS 8개:** R0 2.99%로, 반대로 섞음을 고른다. R2·R4는 0.00%다.
- **BH(묶음이 85% set에서 나음):** R0 6.76%다. 트래픽·작업 집합을 넣은 분류기도 4.9–6.1%로 틀렸다(R2·R3·R4). 회귀형은 R2·R3·R4 모두 0.93%로, 최선 고정 선택과 같다.
  - BH를 빼면 학습 자료에서 "큰 작업 집합"은 BL에만 있고, BL은 CLS도 낮고 트래픽도 많다. 분류기는 레이블만 맞추면 되므로 트래픽·CLS로 나눠도 충분하다. 그래서 CLS가 높은 BH를 SH 쪽으로 보낸다.
  - 회귀형은 BL의 큰 손해(섞으면 27%)를 설명해야 한다. 트래픽은 많지만 손해가 작은 실험 5와 BL을 가르는 값은 작업 집합뿐이라 작업 집합으로 나눈다.
  - 표현에 정보가 있어도 학습 자료가 두 요인을 따로 바꾸지 않으면, RF가 원인을 잘못 짚을 수 있다.
- **트래픽 그대로, 낮은 CLS 4개:** R3(bag-of-words 단독)는 2.45%였다. 이 조건은 실험 8의 SL·SH와 유형별 개수가 같다(트래픽 많은 task 4 + 나머지 12). 남은 R0 부분은 트래픽 맞춤 set과 충돌한다. 연속값 트래픽 통계가 있는 R2는 0.40%다.

최대 regret(조건 단위)은 분류기에서 20–34%, 회귀형에서 8–17%였다.

### 3. 실험 9(고부하·큰 task, 120 set)

**Partitioned 배치(hl-policy: WFD 대 정보 기반)**
- 기준선: 항상 정보 기반 3.29%, 항상 WFD 9.61%.
- 셀별로 나은 쪽이 갈린다.
  - 작은 task만 있는 셀: 정보 기반이 낫다. WFD를 쓰면 9.2–22.4% 손해다.
  - 큰 task 2개 + 코어당 U 0.5·0.7: WFD가 낫다. 정보 기반을 쓰면 7.5·9.1% 손해다.
  - 큰 task + U 0.85: 정보 기반이 낫다.
- 새 task set: R0 1.16%, R1–R4 0.97–1.12%, CLP+U 1.16–1.67%. U 통계만으로 대부분 구분된다.
- 학습에 없던 셀(셀 6개):
  - 분류기는 2.3–3.4%로 "항상 정보 기반"과 비슷했다. 큰 task + U 0.5·0.7 셀에서 정보 기반을 골라 7–9% 손해를 봤다.
  - 회귀형은 R3 1.31%, R4 1.88%, R0 2.04%였다. R3 회귀형은 큰 task + U 0.5 셀에서 WFD를 골라 0.23%였다(U 0.7 셀은 4.38%).

**아키텍처(hl-family)**
- 계열 안에서는 최선을 고른다고 가정한 비교다.
- 항상 Partitioned 0.92%에 대해, 새 set은 0.64–0.94%였다. 새 셀은 0.88–1.14%로 항상 Partitioned와 같은 수준이었다.
- Clustered가 유리한 영역은 실제로 있었다.
  - 큰 task + 코어당 U 0.5·0.7 셀에서 "항상 Clustered(세 변형 중 최선)"의 regret은 0.06%·0.60%였다. 항상 Partitioned는 0.87%·2.65%였다.
  - 작은 task만 있는 셀에서는 Clustered가 5.2–10.4% 손해였다.
- 그 셀을 학습에서 빼면 RF는 대부분 Partitioned를 골랐다.
  - 예외는 R3 회귀형의 U 0.5 셀로, 0.13%였다.
  - 셀 6개로는 경계(큰 task 유무 × 부하)를 배우기에 자료가 부족하다.
- R0·R0-CLP 분류기는 deadline을 놓친 Global을 가끔 골랐다(120 set 중 평균 0.2–0.8개).

**P-first(Partitioned 배치만 RF로 고르고 Clustered·Global은 쓰지 않음)**
- 7구성 전체의 최선 대비 regret이다.
- 배치를 완벽히 고르면 0.92%다. Clustered·Global을 쓰지 않아서 생기는 손해가 이만큼이다.
- 항상 정보 기반 4.25%, 항상 WFD 10.57%다.
- 배치 RF는 새 set 1.95–2.09%, 새 셀 2.25%(R3 회귀형)–4.31%(R0 분류기)였다.

### 4. 정리

1. R0(CLS+U)는 트래픽과 작업 집합 크기를 구분하지 못한다. 학습에 없던 조건에서는 "항상 묶음"보다 나빴다(1.81% 대 1.02%).
2. 트래픽·작업 집합의 연속값 통계를 넣은 R2가 가장 효과적이었다(0.40%). R4는 R2와 비슷했다.
   - bag-of-words 단독(R3)은 일부만 개선했다. 경계가 거칠어서 다른 실험과 유형별 개수가 같아지는 경우가 있었다.
   - CLP+U는 본 조건에서는 R2만큼 좋았지만, 새 조건에서는 고정 선택 수준이었다.
3. 회귀형은 새 조건에서 최대 regret을 크게 줄였다. 실험 9의 새 셀에서도 가장 좋았다.
4. 실험 9에서는 아키텍처 선택보다 Partitioned 배치 선택이 regret을 크게 좌우했다(10.6% 대 0.9%).
   - 다만 큰 task가 있고 부하가 0.7 이하인 영역에서는 WFD 배치와 Clustered가 나았다.
   - 이 경계를 배우려면 그런 셀이 학습 자료에 충분히 있어야 한다.

- `protocol.json`: 입력 묶음 SHA-256, 설정, 표본 수·레이블 분포·조건 목록
- `samples.jsonl`: set별 선택지 TAT·TET, 레이블, 1·2위 차이
- `results.json`: 판단 대상 × 교차 검증 × 방법별 지표와 조건별 지표
- `predictions.jsonl`: 방법·seed별 선택
- `collisions.json`, `summary.md`
- 스크립트 사본
- 그림 `precheck-*`
